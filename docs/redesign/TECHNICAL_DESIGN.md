## 2. 不可破坏的约束

1. R02：所有入口执行同一筛选策略，不存在直接调用正式保存接口绕过筛选的入口。
2. 普通日常没有 Record、SourceItem、Asset、DerivedArtifact、SearchDocument、负向指纹或逐条审计行。
3. 来源级游标和汇总可以持久化；不以“同步账本”名义保留每篇跳过日记的 ID。
4. 失败不是跳过；待确认不是正式记录；正式事务成功前不能发出“已保存”事件。
5. 用户编辑、原始来源和 AI 结果分层；迟到结果不能覆盖新版本或用户修改。
6. 正式记录更新后变得无关时，不复制无关的新版本，不自动删除已经保存的旧版本。
7. 只有正式记录的当前可用投影进入普通搜索；来源引用与相关历史版本保留用于回溯。
8. 不向 Day One 写回、不扫描其私有数据库、不用全量持久化缓存规避筛选。

## 3. 数据流与写入边界

```text
手动输入 / 用户选择的 Day One JSON 导出 ZIP / 旧工作区
  → 临时输入会话（正文内存 + 受控媒体读取）
  → 能力、格式、大小检查
  → 多模态筛选
      include → 原文和原件提交 → 正式记录 → 报告任务 → 正式索引
      review  → 最小待确认项（独立命名空间，无普通索引）
      skip    → 清理会话及派生物 → 只增加批次汇总
      error   → 不推进越过失败项的提交进度 → 重试 / 暂停
```

桌面公开的新建入口只组装文字与附件，并在应用层固定 `origin=manual`；ZIP／旧工作区来源定位和版本只能由各自的内部导入用例创建。手动保存入口也只接受手动会话，不能拿导入会话 ID 重新提交。

手动正文、查询附件和筛选输入不进入旧 Chat Message、Event、JournalEntry 或通用持久化任务载荷。筛选阶段优先同步执行于受限 worker；导入调度仅持久化来源级重试位置。正式入库以后才使用可包含正式 recordId 的持久化分析任务。

### 3.1 输入会话与临时文件

- Renderer 仅持有受限 sessionId；文件路径、解码、凭证和模型请求由 Main 管理。
- 用户提供的文件只读打开，不修改或删除原文件。必要转码和切片位于随机隔离临时目录，权限 0700；文件权限 0600。
- 不把未筛选附件提前放进内容寻址保险库；所有 OCR、转写、关键帧同属临时会话。
- 跳过、放弃、锁定、退出、取消和处理失败均执行清理。异常崩溃后在下一次任务开始前清理上次会话残留；清理失败显示任务错误，不标记整个批次完成。
- 桌面版新版 ZIP／旧库迁移临时目录收束在应用数据区的专用 0700 目录，含所有权标记；进程启动时先核对标记、目录类型、所有者和权限，再清理上次中断残留。标记缺失、软链接或清理失败时不删除未知目标，相关任务拒绝继续。正常任务结束仍立即清理各自子目录。此机制不追溯清理旧版本曾直接留在系统临时目录的文件，也不能消除文件系统快照或系统备份中的历史副本。
- 临时媒体处理可能短暂写入磁盘；“不入库”不等于系统层面的物理零痕迹。不得开启内容日志、持久化提示缓存或对临时目录做产品备份。
- 查询会话遵循相同清理规则，但不会调用收录接口。

### 3.2 原件提交的一致性

判定 include 后，先将选择保留的原件流式复制到加密对象库的待提交区域，校验哈希，再在 SQLite 事务中创建正式记录、来源引用及分析任务。成功提交才返回 saved；原件失败则不创建半条正式记录。崩溃留下的孤立加密对象由恢复扫描回收，不能通过搜索暴露。

同一手动会话提交使用一次性 token 和按会话隔离的幂等键，重复点击返回同一个 recordId；同一会话同时只能有一个筛选提交在途，不同草稿即使误用相同操作 ID 也不能互认结果。ZIP／迁移则按稳定来源版本使用可跨次重放的幂等键。失败后的重试不能复制出多条记录。

## 4. 领域模型与存储

以下为新接口的逻辑类型；不沿用 TypeScript 内置的 `Record` 名称。

```ts
type ScreeningDecision = "include" | "skip" | "review";
type EventCategory = "grudge" | "rights" | "danger";

interface ScreeningResult {
  decision: ScreeningDecision;
  categories: EventCategory[];
  reason: string;
  anchors: SourceAnchor[];
  coverage: "complete" | "partial";
  policyVersion: string;
}

// 处理错误通过错误结果返回，不伪装为第四种语义分类。
type ScreenAndSaveResult =
  | { kind: "saved"; recordId: string; reportState: "queued" }
  | { kind: "skipped"; message: string }
  | { kind: "needs_review"; pendingId: string }
  | { kind: "failed"; code: string; retryable: boolean };

interface SourceAnchor {
  sourceVersion: string;
  assetId?: string;             // 正式收录后才生成永久 ID
  temporaryMediaRef?: string;   // 仅在筛选会话中可用
  textRange?: [number, number];
  intervalMs?: [number, number];
  frameTimeMs?: number;
}
```

| 对象 | 关键字段／约束 | 存储范围 |
| --- | --- | --- |
| EventRecord | id、origin、categories、title、revision、occurredAt、recordedAt、sourceRefs、reportState | 仅正式收录；沿用修订历史机制 |
| RetainedSource | connectorId、journalId、entryId、sourceVersion、contentHash、originalRef | 只属于正式记录，唯一约束为连接＋日记本＋条目 |
| Attachment | originalHash、mime、byteSize、vaultRef、processingState | 已收录原件；派生结果独立 |
| AnalysisReport | recordRevision、inputHash、promptVersion、modelProfile、structuredFields、citationRefs、state | 版本化；失败不替换旧成功报告 |
| FieldOverride | recordId、稳定字段键、value、actor、revision、basis | 用户补充独立保存，覆盖投影而不篡改 AI 原结果 |
| MediaSegment | recordId、assetId、interval／frame／textRange、description、embeddingSpace | 正式记录片段；可定位和增量重建 |
| PendingReview | originLocator、version、最小摘录、原因、类别、会话引用 | 独立隔离；不产生 EventRecord，不进入 FTS／向量 |
| ConnectorState | selectedJournals、committedCursor、scanBoundary、policyVersion、lastSuccess、status、aggregateCounts | 来源级；无 skipEntries 表 |

待确认摘录上限 160 个中文字符，原因上限 120 字；需要保留时使用现有加密存储边界，不将摘录另写进 FTS。正式迁移必须验证实际加密路径，不能只给字段取名 encrypted。

Day One 待确认项可保存定位信息，确认时重新读取指定版本。版本已变化则重新筛选，不能确认旧判定后提交新内容。手动待确认仅持有最小摘录和当前进程会话引用；会话失效后要求重新提供原文／附件，不建立隐蔽的完整持久化草稿。忽略即删除候选行及其摘录；允许未来全量重扫再次发现它，不保留逐条“忽略指纹”。

正式记录发生版本变化使用 optimistic concurrency；保存补充信息必须携带 expectedRevision，冲突返回可理解的重载提示。原文段落、图片与媒体片段引用有稳定 ID，不能仅依赖易变的数组下标。

## 6. 筛选、媒体与分析

### 6.1 筛选器

独立的 ScreeningPort 接收输入会话和当前策略，返回经过 schema 验证的结构化结果；不使用具有任意写工具权限的开放 Agent 来决定数据库操作。

提示约束包含：自身关联、实际发生与引用区别、否定句、模糊指代、冲突与风险标签、原始材料锚点、多媒体覆盖。来自日记的指令都是材料内容，不能改变系统策略、触发工具或发送数据到其他端点。

不以模型自报置信度作为唯一阈值。缺少足够上下文返回 review；无明确相关证据且媒体未完整检查时不能 skip。若正文已明确相关但某附件不可处理，可以 include 并把 coverage 标为 partial；报告必须说明该附件未完成，不能给出完整证据结论。

纯音频通过经验证的原生音频理解参与判断，纯视频通过经验证的原生视频理解结合画面和音轨；模型返回的转写、描述与时间片段均标记为 AI 推断。识别到人物但无法确定姓名时标记“人物待确认”，不做人脸／声纹身份推断。

### 6.2 媒体处理

原生多模态输入优先。百炼官方 Qwen3.8-Omni-Flash 支持本地音视频经 Base64 直传、文本输出及 Function Calling；编码后的音视频必须小于 10 MB。小文件直传；Mac 上超过 7,000,000 原始字节的音视频，以及 M4A，现已接入本机有界分段后逐段模型理解，再综合用于筛选、报告或临时查询描述。不要求用户安装 ffmpeg／Whisper，本地工具不作转写或语义判断；不静默截断，也不上传到公开 URL。格式不支持、片段检查不完整或上下文超限时明确失败／部分完成。[官方音视频协议](https://help.aliyun.com/zh/model-studio/qwen-omni) · [官方工具调用](https://help.aliyun.com/zh/model-studio/qwen-function-calling)

单次输入限制遵循 PRD，模型单次长度限制独立验证。分段路径已用模型替身和本机可解码媒体验证，真实模型的格式兼容性、识别质量、定位精度、耗时和费用仍是发布门槛，不能按离线测试推断已通过。M4A 会先转为私有临时 WAV 再调用模型；单张 SDR HEIC 使用下述本机私有图片转换，不把本机解码成功当作真实模型验收。

**2026-09-26 长媒体接口复核。** [Qwen-Omni 官方调用说明](https://help.aliyun.com/zh/model-studio/qwen-omni)仍要求本地音视频 Base64 编码内容小于 10 MB，较长文件的示例改用模型可访问 URL。[Responses 字段说明](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)列出音视频 URL／Data URI 输入，但未给出上传后 `file_id` 作为 Qwen3.8-Omni-Flash 音视频输入的契约；[独立文件 API](https://help.aliyun.com/zh/model-studio/files-api/)的资源用途和保留期也不能据此推断为 Omni 私有媒体输入。故本版拒绝超限本地直传，不上传私有原件到公开 URL；2026-09-28 已选择并接入下述本机有界分段路径，不依赖未经验证的云文件用途。

**2026-09-28 本机分段基础层。** `NativeMediaSegmentPort` 接收带大小与 SHA-256 的流式来源；Mac 适配器先核对私有处理副本，再调用随包构建的 AVFoundation 小工具。单个来源不超过 500 MiB，每段最多 120 秒、原始导出字节不超过 7,000,000，最多 128 段；超过数量或最小片段仍超限时失败，不把前缀当作完整覆盖。视频优先直接封装为 MP4，过大片段缩短后重试；本机音频转换为保持原采样率及单／双声道的 16-bit PCM WAV，按统一原件采样网格计算边界并保留时间间隔，不静默混音多轨或多声道。输出提供连续原件起止时间，并核对导出时长；这不证明逐帧内容或真实模型时间定位准确。

处理目录为独立 `0700` 目录，副本为私有文件；完成、异常、消费者提前结束及中止后清理，进程退出后才删除处理目录。清理前重新核对目录身份和所有权标记，未知目录不递归删除，清理失败明确报告。工具禁止容器引用外部本地媒体或远程地址，诊断仅使用固定代码，不回显框架错误、原件文件名或内容。视频文件大小采用处理期间监测与导出后硬性核对，不能据此承诺任意编码器内部内存或瞬时磁盘峰值。

开发构建使用本机 SDK，产物包含 `arm64`／`x86_64` 两种架构、最低编译目标为 macOS 13；成品运行只依赖系统框架，不需要 Xcode／第三方转写工具。开发、构建和桌面测试命令会准备工具；显式执行 `pnpm test:mac-media` 生成可解码的虚构 WAV／MP3／M4A／MP4／HEIC 并运行本机门禁，默认测试不假装具备真实媒体环境。上述本机门禁当时没有真实模型请求；2026-10-01 的有限付费烟测见 §7。Apple Silicon 与旧版 macOS 的运行兼容性仍待相应环境验证。

**2026-09-28 业务接入与边界。** 每段使用只读结构化工具返回实际覆盖、概括和保守观察；片段 ID、相对时间、连续覆盖直到原件末尾均须有效，格式错误最多修复一次。相对位置只换算一次；无法精确定位的观察锚定整段，明确标为需核对的 AI 描述。单文件完整描述限 256 KiB，单任务逐段上下文限 512 KiB，超过即失败，不截掉后段。筛选在任一片段失败时不作安全跳过；报告可继续整理已检查的材料，但注明未完成，保存逐段描述以供原件核对和正式索引。报告读取保险库的流式来源，先在私有副本完整完成 GCM 认证、大小和摘要核验，再调用任何片段模型；不使用 64 MiB 预览缓冲接口。

媒体查询选择时的摘要仍只保留于内存；长媒体通过带摘要的流式来源参与分段，全部检查后才综合成临时检索描述，不写正式记录、附件或查询索引。取消、锁定及模型配置变化会阻止后续片段请求和迟到结果；暂停后立即重新启用相同配置也不能复用旧任务。并行成功的模态能力标记不会使其他任务失效。已发送的服务端请求仍可能完成或计费。隔离桌面测试用 48 秒合成 WAV 与模型替身验证筛选、加密报告、跳过、检查不完整、报告及查询取消后重试、加密副本损坏时零片段调用及恢复重试；不是识别质量验收。

新建与搜索的分段进度仅发送会话／媒体 ID、文件序号、当前阶段／片段及已检查原件时间；不发送路径、正文、密钥或未经确认的预计片段总数。预加载验证字段并丢弃异常事件，界面只接收仍在运行的当前会话，取消／重试后拒绝旧结果。搜索有独立取消入口，等待停止和临时副本清理后才可重新提交。报告通过已有作业进度呈现，明确为任务处理百分比，不等于媒体覆盖率。保险库解密流关闭、取消或消费者提前退出时，也关闭底层加密文件流；两种保险库格式都有真实文件句柄生命周期回归，不只断开上层消费者。

**2026-09-28 HEIC 本机转换。** `NativeImageConversionPort` 使用同一随包工具的 Image I/O／CoreGraphics 路径；筛选、报告、图片预览、正式图像索引及临时图片查询均在本机转换后再使用 PNG／JPEG。仅支持自包含、单张、8-bit SDR 图片，输入限 20 MiB、50,000,000 像素；多图、辅助图像、已识别的 HDR／扩展色域范围、外部数据引用、坏容器和超限明确失败，不静默选择首图或压小分辨率。容器头有界检查先于系统解码，拒绝 PQ／HLG 声明及辅助引用；实际 HDR 相机样本兼容性仍待最终验收，不以合成标签测试代替真实样本。

应用照片方向并核对完整输出尺寸后，复制到新 RGB 光栅，不把原始 GPS／EXIF、缩略图、标识或 maker notes 交给编码器。优先 PNG；超过 7,000,000 字节时仅尝试固定 0.95 质量的全尺寸 JPEG，仍超限则失败，不反复降低质量；带透明度的来源不走该 JPEG 回退。副本的生成尺寸和色彩描述可能由编码器重新写入，并不等于保留源照片元数据。八种方向与四色块合成测试核对旋转／镜像及尺寸，模型请求和界面明确标记转换副本可能有编码差异。方向应用采用 [Image I/O 方向转换选项](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform)，完整尺寸由本应用另行断言。

转换使用独立 `0700` 目录和 `0600` 文件，来源字节在异步操作前快照并校验副本摘要；输出硬限通过有界编码回调及读取后校验落实。完成、失败或取消后等待进程停止再核对目录身份／所有权标记并清理，遇到未知内容或目录替换拒绝递归删除。保险库预览／索引先完整认证原件并核对大小与 SHA-256，失败不转换或发送给模型；锁定／换工作区使预览失效，卸载后的迟到预览不创建 Blob。仅保存加密原始 HEIC，正式来源锚点及图像索引内容摘要仍指向原件；转换副本不作为新附件、缩略图或查询持久化。界面的“保存副本”导出原始 HEIC，不导出分析用光栅。真实 API 格式、质量、费用、真实 Day One 导出及目标设备运行仍未通过验收。

**2026-09-28 私有音视频原件预览。** 音视频播放器不再走 64 MiB 内联字节／Blob 接口；图片接口继续保留原有上限。Main 从保险库流式复制到独立 `0700` 处理目录的 `0600` 原件副本，完整完成 GCM 认证、大小与 SHA-256 核验，再通过随包工具检查自包含容器及对应媒体轨道，之后才发布播放能力。副本保留原始字节与固定媒体后缀，不转码，不调用模型。当前接受 WAV、MP3、M4A、MP4、MOV 的受限 MIME 类型；具体编码能否播放仍取决于本机 Chromium，失败明确提示保存原始副本后核对。

单原件限 500 MiB，同时最多 4 个预览、合计预留不超过 1 GiB，每个预览最多 4 个并发读取，最长存活 4 小时。IPC 只传请求／附件 ID、MIME、大小及随机 256-bit 的 `gv-preview://media/…` URL，不传路径或原件字节。协议只注册在主窗口独立的非持久化 Session；`standard`／`secure`／`stream` 开启，但不绕过 CSP，也不开放 Fetch API。仅允许当前主页面的真实请求来源和 GET／HEAD；缺失来源、外部来源、URL 额外路径／查询／片段均拒绝。项目锁定 Electron 43.7.2；原 43.4.1 没有所需的来源字段，真实桌面测试曾返回 403。来源依据 [`initiatorOrigin` 的官方新增契约](https://github.com/electron/electron/releases/tag/v43.7.0)而非页面可控制的 referrer，播放协议遵循 [Electron 官方协议说明](https://www.electronjs.org/docs/latest/api/protocol)。

读取支持完整响应和单一 HTTP byte range／suffix range，拒绝无效或多范围请求；每次打开核对目录、文件身份及修改时间，以最多 64 KiB 分块响应并遵循消费背压，使用 `no-store`／`nosniff`。关闭、取消准备、详情卸载、锁定、切换工作区、页面导航／渲染进程退出或应用退出时，撤销 URL、中断读取并等待文件句柄或检查进程停止后清理；迟到的渲染响应也会再次释放原请求。工作区创建／打开／恢复／备份恢复失败但会话仍打开时，允许重新申请预览，旧 URL 不恢复；清理失败仍禁止申请。清理前检查所有权与目录身份，未知内容或软链接不递归删除，失败禁止继续打开预览并明确报错；崩溃残留沿用专用临时根的启动回收机制。Chromium 仍可能预取已认证副本的更多字节，不能据此承诺其内部缓存、解码器或整个应用 RSS 恒定，也不能保证系统快照和物理存储中的明文被安全擦除。真实大视频编码、长时播放、目标设备峰值内存及异常断电仍需最终本机验收。

### 6.3 正式报告任务

同一记录修订的 queued／running 分析任务合并；持久化任务 ID 是单次分析运行的幂等身份，同一任务中断后重放不能写出另一份报告。用户主动重新分析会创建新的任务 ID，即使原文、模型和提示版本未变，也可生成新的报告版本；新尝试若仅部分完成，同修订的旧完整报告仍作为当前可见版本。状态为 queued → running → succeeded／partial／failed／cancelled。初始并发 2，按服务商限制调整；可重试错误采用 2、8、30 秒退避，之后保留失败状态供用户重试，不无限消耗额度。

JSON 校验失败允许一次受限格式修复，仍失败则不发布报告。重新分析期间继续展示旧报告及“更新中”；结果与当前输入版本不一致时保存为历史或作废，不能替换当前投影。用户覆盖最后合并，事件级法域也是受保护的用户字段。

时间线与搜索入口共用详情读取生命周期：先订阅任务通知，再发起首次读取；通知到达后只刷新当前记录，不重新执行搜索或调用模型。只有仍存活的同一选择及最新读取请求可以更新界面，返回列表、切换记录或卸载后拒绝迟到成功与错误，也不接受比当前更旧的记录修订。应用用户编辑结果后再读取一次最新详情，避免编辑响应与任务完成通知交错时漏掉新报告。刷新失败保留上次成功读取的内容并提供重新载入入口；报告更新不重置当前页签或未提交的编辑内容，返回时继续恢复原列表条件和位置。此界面生命周期不替代服务层报告版本竞争保护。

**2026-09-29 报告字段精度与人物补充。** 详情不再丢弃报告时间的 exact／approximate／range 精度，显示相应标识；用户覆盖日期、月份、相对时间或范围时保留其原精度，不补造缺失的日、时、分。模型标为 unknown 或空的时间值不作为具体时间显示；新报告的适配器也去掉这个冲突值，保留待补充提示和固定说明，不把它写进报告投影或搜索。字段未知不是处理失败，单凭这种缺失不会把已完成分析改为 partial 或触发重试。旧已存报告只在界面防止 unknown 具体值冒充事实，不在当前用户工作区回填、迁移或改写历史索引。

人物按项展示姓名、已有角色和原始材料／AI／用户来源标识；标识不等于事实已核实，不自动识别人脸或声纹，也不猜缺失角色。人物为空仍有明确占位和“补充人物信息”入口：写入既有受保护的 `clarifications` 用户陈述，而不是直接改写 AI 的人物或伪造身份认证；重新分析输入包含该陈述，原文不变，搜索可覆盖用户补充。编辑器取得键盘焦点，当前模型报告没有再列出同一问题时，补充仍在“此前补充的问题”可见。合成报告含 unknown 与具体时间冲突、混合人物来源和长字段的桌面回归不证明真实模型提取准确度，R04 内容验收仍需用户最终授权实测。

**2026-10-02 用户发生时间编辑。** 底层原已接受六种`TemporalValue`，旧详情编辑器却只能提交精确日期。现独立编辑器支持日期、月份、范围、相对／大约描述、明确带时区的时刻和显式unknown；打开已有值保留其表示，不将月份补成月初或把自然语言解析成某一天。范围可留空一端，完全未知须显式选择unknown；已知倒置日期／月份／时刻范围在界面拒绝，月份终点保留整月可能性。相对描述按既有IPC的200字符串单元上限校验，范围两端各200，不静默截断。带明确偏移的时刻转换为同一UTC时刻以兼容既有Main契约，缺时区或可能丢失次毫秒的偏移输入明确拒绝；已有UTC文本可原样保留。

保存仍走受信`patchFields`和expectedRevision，冲突保留用户输入及模式；取消不写入，编辑本身不创建模型任务。unknown写为受保护的用户时间字段，重新分析不能恢复旧AI日期。该改造只补齐Renderer入口及布局，不新增表／IPC、不改写原文、附件或历史记录，也不自动迁移已有用户值。30项新增回归覆盖表示／验证与详情提交；独立桌面六种保存→重新分析及unknown重开，实际1440／1024／840／390px宽度检查和范围编辑截图见实施计划。这里的模型是合成替身，不构成真实时间事实、模型质量或全部页面验收。

### 8.4 无负向缓存下的可靠进度

以一页为提交单元，保存“本页开始游标”。逐条处理期间，只把正式记录／待确认写入对应集合；本页全部成功处理且临时数据清理完毕后，原子提交汇总及 nextCursor。页内错误保留本页开始游标，恢复重放该页；正式记录唯一键去重，跳过内容重新筛选。批次汇总只在页提交时增加，避免重放重复计数。

不允许时间水位越过失败项。若来源分页在并发编辑时不稳定，必须使用快照边界或重叠扫描并完成完整性验证；没有来源保证时采用完整扫描周期，不能自行假设 editDate 排序足够。

首次全量筛选完成后提交可用的变更起点；结束边界附近的新增修改补一次扫描。没有变更 feed 时每个周期都覆盖所有条目，不能只看近期日记日期。暂停不推进当前页；取消清理临时会话，保留已收录记录和已提交进度。

## 9. 多模态检索

R08 使用独立 QuerySession；输入不经过“保存为记录”流程。文字、图片、音频、视频可组合，所有检索条件先解析，再执行召回：

1. 正式原文、报告、用户字段、OCR／转写做 FTS5 关键词召回。
2. 文本和图像使用同一经验证多模态向量空间；音视频查询先由原生理解 API 生成仅当次有效的描述，长媒体按 §6.2 在本机完整分段后逐段检查，再与正式报告中带附件锚点的经过或独立媒体片段描述做文本语义匹配。媒体片段仅采纳模型明确确认检查过的附件；音视频缺少可核对时间定位的描述不进入片段索引，并使报告呈现覆盖不足。片段描述也纳入正式记录关键词索引。当前不是音视频原件的直接向量／精确指纹索引；无匹配片段、分段超限或模型能力不足时明确显示限制，不把描述匹配说成原件全部内容必然可召回。
3. 每条召回携带 recordId 和 SourceAnchor，使用 RRF 融合，记录级聚合展示最相关的 3 个片段。
4. 搜索原件、报告和派生物可以共同命中，但界面不重复显示同一记录。

**2026-09-29 原文文字定位。** `textRange` 采用未改写原文的 Unicode 码点半开区间，不能把大小写转换后的 UTF-16 偏移直接用于原文。关键词仍沿用整串 `zh-CN` 小写匹配，不新增 Unicode 归一化或改变召回规则；匹配后按每个原文码点的转换宽度换算起止位置，查询命中某个展开字符的一部分时定位整个原字符。`İ` 的默认小写会展开为两个码点，希腊词尾 Sigma 则有上下文替换，依据见 [Unicode 特殊大小写规则](https://www.unicode.org/Public/UCD/latest/ucd/SpecialCasing.txt)。整串匹配保留上下文语义，宽度校验不一致时不发布虚构精确位置。没有改写原文、查询、既有索引或用户数据，也不保存折叠文本／位置映射。纯关键词和关键词／语义融合共用正确的原文位置；合成桌面检查点击命中后高亮原始“目标”，完整原文保持不变。

**2026-10-02 设置页读取所有权与未知状态。** 模型配置、索引状态和默认法域分别由`useReadOnlySnapshot`管理；载入、失败、最新成功值及成功读取代次分开。首次读取失败不显示“未配置／未建立”，法域未读到前不填入可保存的中国大陆默认值。可保留上次成功配置与用户当前表单输入，但明确标注旧快照；能力状态未确认时不标可用或不可用，新的连接测试／索引构建／导入／迁移在相关读取恢复前禁用。保护性暂停仍可针对上次已启用状态执行；读取失败提供各自只读重读，不重新连接或请求模型。

**2026-10-02 Renderer 会话所有权。** 应用壳的工作区状态和待确认读取归入 `useWorkspaceSession`，使用仅在内存中的会话对象与独立读取序号。先订阅锁定通知再读初始状态；通知立即撤销所有权、清空待确认及旧输入／详情选择，卸载工作区内容，显示状态读取中，直到最新读取明确返回。读取失败是状态未知，不冒充已关闭或解锁成功；重读按钮仅重读状态，不打开工作区、恢复输入或外发模型。待确认读取同样明确区分载入／失败／真正空集，重读只读取列表。

**2026-10-02 时间线读取状态。** `useTimelineRecords` 将当前条件、最近成功列表、载入／刷新／分页及读取失败分开。首次或新条件读取失败不能显示“还没有记录”；切换条件立即隐藏旧列表，最新成功的空集才显示空状态。同一条件的后台刷新或分页失败可保留最近成功内容，但明确说明不是最新读取结果并提供只读重载；刷新期间已有页保留，先前空集不提前作为新结果显示。

**2026-09-29 日期筛选与排序补充。** 时间线、本地关键词及完整语义召回共用正式记录日期投影，以查询捕获的本地时区解释明确时刻，纯日期／月份不视为 UTC 时刻。日期边界均包含：月份覆盖该月所有可能日期；范围按起点下界与终点上界判断是否可能重叠，不只比较起点。范围中缺失或不可解析的一端保持开放；空范围、两端不可解析、倒置范围、相对／未知时间或非法日期回退到原有记录日期，不解析自然语言或自动猜测发生时刻。发生值依本节当前报告／用户读投影选择，不把任意报告时间文字物化成来源事实字段。

**2026-09-29 本机界面生命周期补充。** 新建和待确认均为明确的模态对话框；焦点仅在最上层面板的可用控件内循环，后台节点暂时 inert，关闭后恢复仍有效的发起控件或下层编辑器。后台隔离和滚动锁按层计数，并保留原状态，嵌套面板或非顶层先卸载不会提前解除隔离；StrictMode 的建立／清理重放也有回归。关闭待确认不丢弃下层完整输入，放弃编辑仍走原确认与会话清理路径，不新增输入持久化。

报告与新建的长字段、连续无空格标题和文件名允许换行，编辑器在窄窗口重排而非裁掉按钮；状态标签不再被网格／弹性布局拉到整块标题高度。隔离 Electron 检查 1440／1024／840／390px 的时间线、报告、原件、标题／地点编辑、待确认、新建与跳过、搜索结果及详情、模型与导入设置，既核对页面，也核对子容器未溢出；图片复核检查长文件名和窄屏设置。仅证明这些合成路径，不宣称全部条件状态、真实材料和人工可用性均通过。

**2026-09-29 Unicode 输入边界补充。** 新建正文上限 50,000、查询上限 500，按 Unicode 码点计数，与原文锚点和已有应用层计数一致；增补汉字及单个非 BMP emoji 不按两个 UTF-16 单元计数。组合字符、连接符及组合 emoji 仍按所含码点计数，不宣称为可见字形数量。界面、受信 IPC 和应用层共用限值／计数；关键词查询也在修剪空白前检查原始输入。输入框不使用会按 UTF-16 静默截断的 HTML maxlength：超限保留完整输入、提供可访问提示并禁用提交，提交处理自身仍校验，Main 拒绝绕过界面的超限值。HTML 原型的新建检查采用同一计数口径。没有放宽模型上下文、附件上限或新增输入持久化；模型本身能力不足仍明确失败。

**同日时间线展示精度。** 月份保持 `YYYY-MM`，范围用完整原始两端分组并标“时间范围”，缺失端以问号显示，不把月份补成月初或把区间压成首日。未知、相对时间、空范围、非法或矛盾旧时间按记录日期排序／筛选，标题和卡片明确标“记录日期”；相对描述及完整原始范围仍可看到，不以格式化失败丢弃或改写。纯日历日期直接按年／月／日显示，明确带时区的有效时刻才按查询捕获时区格式化；跨到公元前的时刻保留纪元，不能显示成公元后的同名年份。自然语言不推算年份／时区，非法日期不滚动到另一天。区间规则见本节日期筛选补充；展示检查不证明时间事实准确度。

**当前报告时间的可逆读投影。** 新的手动／ZIP 收录不再把正文中的第一个日期或相对词当作发生时间：合同、引文、约定及多个事件可能各有日期，筛选结果尚不提供有语境的时间字段，初始发生值为 unknown，记录日期保留。当前报告结合本次材料整理发生时间，或由用户显式补充；旧版迁移的结构化发生字段仍按迁移合同保留，不改写既有历史值。原始 `occurred_at_json` 保持旧结构化字段／用户显式修改，报告不会改写该列、来源、附件或修订。读取详情、时间线、关键词候选和完整语义候选时共用选择：用户发生字段覆盖（包括明确 unknown）优先；否则只选择当前记录修订的可用报告，与详情一致地优先 complete、再按更新时间／行序选择；无当前已知报告则用原字段。旧修订／失败报告不进入日期投影，新的 unknown／空值不把矛盾具体时间提升为已知；既有成功报告不因同修订 partial 结果降级。其他字段编辑只保留原始发生列，不把曾读取的 AI 日期物化回来源；记录修订改变后旧报告时间自然失效。

报告值只在整项是 ISO／中文年-月-日、年-月或明确带时区时刻时形成相应日历单元，不提取叙事中任意一个日期；约／大约只在报告原精度为 approximate 时作为标识移除，粒度与 approximate 元信息保持，没有猜测误差宽度。range 支持完整两端及显式开放端，自然语言端点不推算；不完整年份、无时区钟点、多种日期说法或无法解析文本继续作为完整相对描述，并明确显示记录日期回退。日期筛选仅匹配报告／用户给出的日历粒度，不保证现实发生时间或事实已核实。`occurredAtSource`／`occurredAtPrecision` 是可逆返回元信息，卡片和详情显示 AI／原始材料／用户来源及大约标识；无来源的旧字段不被补标为原始事实。

这些投影只有瞬态读取，不新增表／升级标记，不重新分析／重建向量；既有已保留报告可在新版重开时直接使用。报告分析提示明确上一份 AI 时间不是已确认新事实，要求按本次原文／原件／受保护用户陈述重核对。受保护的 unknown／空时间输出待补充，不保存内部 temporal JSON 为时间正文；相对与范围用完整有意义文本，用户补充不被新报告改写。用户旧库升级及真实模型时间／法律适用质量仍未验收。

**2026-09-29 筛选反馈作用域补充。** 新建正文、有效附件集合发生变化后回到编辑态，清除上一份输入的失败／跳过／待确认提示；不能把旧结论继续呈现为新输入的结果，也不因编辑自动调用模型。取消文件选择或空拖放不改变输入及反馈。文件选择事件先快照 File 对象，再清空原生选择控件，允许移除后重新选择同一文件，不清空编辑器实际保存的附件对象；提交中仍拒绝修改。清除编辑器反馈不会自动删除已经生成的最小待确认项，后者仍对应先前输入，需要用户确认或忽略。HTML 原型也清除旧反馈并恢复按钮文案，保留其明确的模拟场景边界；文件内容不在原型中读取。

## 11. 迁移、日志与验证

### 11.1 迁移

**2026-10-01 打包与配置位置连续性。** OS 的应用名称／ID 与包内运行时名称分别核对：Electron 优先使用 `package.json.productName`，默认 `userData` 依运行时名称选择，仅 Info.plist 正确不能证明最近工作区和模型配置可恢复。[官方说明](https://www.electronjs.org/docs/latest/api/app#getname)。测试版构建固定此前可用版本的 `name: grudge-vault-redesign-preview`／`productName: Grudge Vault 测试版` 和独立应用 ID；正式版保留原 `@grudge-vault/desktop` 运行时名称，不顺带移动旧配置位置。包检查器拒绝这两个名称合同的漂移，并保留当前生产入口与原生工具一致性检查。先在独立空配置检查实际运行时名称，再经用户授权覆盖指定测试版及核对原配置；不能用空配置启动代替实际原工作区恢复证明，不迁移／删除误启动留下的其他配置目录。

创建独立新版工作区，从旧库只读扫描，使用相同筛选器。正式记录保留源 ID 映射、修订、用户补充和所需附件；待确认最小化；普通日常不复制。若旧 Source／Event 已表达同一日记，按来源关联聚合，不能双重建档。

旧加密对象通过原工作区正常解锁后流式解密并重新加密到新工作区，不直接拷贝依赖旧 key ring 的密文。引用在迁移事务中重写；无法迁移的关系列入汇总问题，不能静默悬空。旧工作区保持不变，只有新库检查通过后才切换最近工作区。

**2026-10-01 迁移取消与目标所有权。** 批量旧库迁移使用本地操作控制器与外部取消信号的组合；清空瞬态会话时同时停止迁移。开始扫描、每条输入、输入准备及筛选返回、异常降级和扫描完成均重新核对取消状态／会话代次／原目标记录仓库；空扫描也不能在已经取消时宣称完成。无法读取或格式无效可产生最小待确认，但取消和工作区失效不属于该降级原因，不能捕获为待确认。输入准备接收组合取消信号，输入会话仅在内存绑定目标记录仓库；准备结束、使用会话和每次附件上传后的正式提交边界均核对该所有权，迟到的include／review不能转写另一工作区或在原目标失效后提交。未提交的加密对象仍按原仓库引用情况回收，已提交记录保留，来源关闭及控制器释放仍在finally执行。14项新增合成回归覆盖上述边界和正常最小待确认，不代表真实旧库、系统保护或断电验收；已安装包尚未包含本修复。

用户主动保存解密原件副本时，目标必须位于加密工作区真实路径之外；解析目录软链接后仍落在工作区内的目标拒绝写入。图片预览使用有界内存及受限转换副本；音视频使用 §6.2 的完整认证私有磁盘副本与会话 URL，可以预览超过 64 MiB 的原件。外部目标仍以流式方式导出原件；预览限制不改写或删除用户来源。

**2026-09-30 工作区交接与失效通知。** 桌面的创建、打开、恢复包导入和备份恢复先撤销原件预览，再等待旧后台任务响应取消并完成仓库状态写回，随后才允许关闭原会话的数据库及密钥。不论切换成功或失败，后台执行器按管理器的实际活动会话重新绑定：选择被拒但原会话仍可用时恢复原执行器；原会话关闭异常并失效时不恢复预览或作业，通知界面进入锁定恢复入口。显式锁定即使关闭步骤报错，也按实际非 open 状态发送通知。界面收到通知即卸载输入／待确认面板，清除过期选择，重新读取工作区状态；解锁后不重开旧会话的输入。启动页操作失败也会主动重读状态，不依赖通知一定抵达。故障注入只存在于隔离 E2E 入口，生产入口不提供关闭故障开关；这些回归不代替真实系统保护、磁盘故障或异常断电验证。
