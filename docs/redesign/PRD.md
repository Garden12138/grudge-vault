# Grudge Vault 精简版产品需求文档

版本：1.2 · 日期：2026-10-02 · 状态：个人本机功能重构已交付；发布级验收延期

配套文档：[实现方案](TECHNICAL_DESIGN.md) · [UI 原型](UI_PROTOTYPE.html) · [实施计划](IMPLEMENTATION_PLAN.md)

## 1. 产品定位

一个个人使用的 Mac 事件账本，帮助用户记住冲突、受辱失信、权益可能受损以及人身或财产安全风险，保存相关材料、整理经过、补齐事实并形成处理建议。

**所有入口先筛选，再入库。普通日常不属于本产品，不建立记录，也不作为隐藏资料保存。**

用户无需管理“候选事件、人物实体、证据库、案件、Agent 模式”等技术或组织概念。核心路径是：手动输入或导入 Day One 导出包 → 判断是否收录 → 记录与分析 → 时间线回看或多模态搜索 → 补充信息。

本轮在本机代码中实施；模型密钥与真实账户调用由用户在最后自行配置并授权。下述未通过实测的能力仍是验收目标，不表示已可用。

**2026-10-02 本机个人使用验收调整：** 用户要求不把非产品功能类验收复杂化。本轮继续实现R01—R10的产品功能，以安装启动、输入与导入、时间线／详情／补充、搜索及失败恢复的功能自测为交付依据；保留筛选先于持久化、原件与用户修改保护、去重、隐私及状态诚实等必要回归。双人独立标注、200条真实模型质量评分、正式签名公证及其他设备的发布证明留待正式发布，不作为用户本机先用的前置条件，也不再要求用户为此提供独立标签。延期不是这些指标已通过；现有模型质量、法律适用及真实媒体兼容性的未验证限制仍须如实说明。额外付费测试和真实数据迁移仍按用户明确授权执行。

## 2. 用户、目标与范围

### 2.1 目标用户与使用场景

- 发生争执、被冒犯或受到威胁后，快速保存文字和现场材料。
- 工作、消费、合同、金钱等方面的利益可能受损，需要整理事实和行动步骤。
- 已经用 Day One 写日记，希望按需导出 JSON 后筛选导入值得留存的相关事件。
- 记不清日期或用词，但能提供一句描述、一张图片、一段录音或视频，找回相关记录。

### 2.2 成功标准

| 目标 | 验收口径 |
| --- | --- |
| 操作简单 | 从时间线点击一次即可进入新建记录；不要求先创建人物、案件或资料分类 |
| 收录准确 | 手动、Day One JSON 导出 ZIP 和旧数据迁移均通过统一筛选；无“强制保存普通日常”入口 |
| 结果可理解 | 每份报告都呈现时间、地点、人物、事件和建议；未知内容以待补充表达 |
| 原始内容可信 | 原件可回溯；AI 提取、用户修改和法律依据有不同来源标识 |
| 搜索可定位 | 四种查询输入均能找到相关正式记录；音视频结果可定位时间片段 |
| 状态诚实 | 入库成功后才显示“已保存”；筛选失败与无关内容不混淆 |

### 2.3 版本边界

首版为中文优先的 Mac 桌面应用，延续本地存储和用户自行配置的模型服务。主导航仅保留时间线、搜索、设置；新建记录为固定主按钮。

本轮不建设 Day One 直连或定时同步、通用日记、聊天助手首页、独立人物管理、案件管理、材料中心、社交分享、移动端、多设备同步、退出应用后的后台服务及自动对外维权。已有复杂模块退出主流程，底层可复用能力保留。

## 4. R02：收录规则

### 4.1 判断对象与类别

判断对象是用户实际经历、与用户利益或安全有关系的具体事件；不要求已经构成违法或已经取得完整证据。允许多标签：

- **记仇／冲突**：侮辱、冒犯、排挤、背叛、失信、不公平对待及明确希望留存的具体负面经历。
- **权益可能受损**：涉及工作报酬、财产、消费、合同、隐私等自身利益的争议。
- **危险／安全风险**：与自身有关的威胁、跟踪、骚扰、暴力、事故隐患或财产风险。

仅有“今天不开心”等情绪、含糊指代或可能相关的描述，进入待确认。普通吃饭、通勤、散步、工作进展、旅行等没有相关风险的内容跳过。仅有标签或关键词不足以认定收录；否定句、新闻引用、影视情节、梦境和虚构故事要结合上下文判断。

### 4.2 四种结果

| 结果 | 界面文案 | 是否正式入库 | 后续动作 |
| --- | --- | --- | --- |
| 收录 | 已保存，正在分析 | 是 | 生成报告、媒体索引，进入时间线 |
| 跳过 | 不属于收录范围 | 否 | 清理处理副本；手动输入留在当前编辑框 |
| 待确认 | 是否与你有关，或需要留存？ | 否，仅最小待确认项 | 用户保留或忽略 |
| 失败 | 未完成判断，请重试 | 否 | 保留当前输入或来源级重试位置 |

待确认不是绕过筛选：只向确实无法确定的内容提供“保留”，判断为普通日常的内容没有强制入库按钮。用户补充了新事实后可以重新提交筛选。

### 4.3 多媒体与混合日记

图片、音频和视频与文字同等参与判断。正文“今天正常下班”但视频包含威胁，不能仅凭正文跳过。媒体缺失、无法解码或模型不支持时不能产生“已完整检查，无关”的结论。

同一篇日记中，只要有明确相关事件，就收录为一条记录；完整原始来源用于回溯，卡片标题、摘要和报告聚焦相关部分。不会为其中普通日常单独建立条目，也不自动拆成多条时间线记录。

### 4.4 普通日常零条目存储

- 不保存正文、附件副本、摘要、OCR、转写、缩略图、向量或逐条来源标识。
- 不建立“已忽略日记”“回收站”“隐藏原始资料”等逐条存储。
- 只允许导入批次级执行状态和汇总计数；“跳过 86 篇”没有可打开的日记清单。
- 临时处理文件、子进程缓存和失败残留必须清理；日志、错误上报、模型审计不能保存被跳过内容。
- 不要求删除 Day One 原日记、用户选择的本地附件或原始 ZIP；本应用无权修改这些来源。
- 云端筛选意味着内容可能发送给选定服务商。“不入库”指本应用及其管理的缓存，不声称服务商零留存；启用时说明这一边界。

## 5. R03：手动记录

1. 点击“新建记录”，输入文字或选择图片、音频、视频；可只有媒体。支持拖放、粘贴图片和多选附件。
2. 点击“保存”。空输入不可提交；先检查格式和能力，再显示“正在判断是否收录”。
3. 明确相关：保存原文和原件成功后进入详情，显示“已保存，正在分析”。
4. 普通日常：停留编辑器，显示“不属于收录范围”，当前内容可修改或清空。
5. 不确定：显示原因，可加入待确认，也可补充事实后重新判断；不自动建立正式记录。
6. 失败：保持输入，提供重试及可理解的原因；没有模型时提示先完成设置。

通过筛选前，不建立持久化草稿；当前编辑内容仅保留在内存。离开有未处理输入的页面时询问是否放弃，关闭应用后不能恢复。待确认只保留最小摘录，不能替代完整草稿；手动原文或附件在会话结束后不可取得时，确认前要求重新提供，不以摘录冒充完整原文。

首版输入基线：文字最多 50,000 字；单次最多 20 个附件，每个不超过 500 MB；图片支持 JPEG/PNG/WebP/HEIC，音频支持 MP3/M4A/WAV，视频支持 MP4/MOV。兼容性验证前不得把格式显示为已支持。长音视频分段处理，不静默截断；超出当前能力时提示调整输入。存量 PDF 保留为来源附件，首版新建入口不扩展 PDF 分析。

## 6. R04、R05：报告与补充

### 6.1 报告结构

| 区域 | 内容与编辑方式 |
| --- | --- |
| 事件摘要 | 一句话概括，可编辑标题 |
| 时间 | 发生时间、精度、来源；未知显示“待补充：大约何时发生？” |
| 地点 | 明确地点或待补充；不从环境照片猜测精确地址 |
| 人物 | 用户、相关人及角色；不默认进行人脸或声纹身份识别 |
| 事件经过 | 按顺序整理，链接对应原文、图片或音视频片段 |
| 缺失与争议 | 将未知、冲突说法和推测明确分开，可逐项补充 |
| 解决建议 | 可执行步骤、材料缺口与不同选项 |
| 法律视角 | 仅权益相关事件重点展示：可能涉及的权益、待核验问题、依据和行动顺序 |

占位不是默认事实。用户编辑后标记“你已补充”，重新分析时作为有来源的用户陈述；不会覆盖用户字段。更新原文或附件会使旧报告标为“来源已更新”，新报告成功后再切换版本。

### 6.2 法律分析

默认法域为中国大陆，事件级可修改。结合事发时点、地点、关系和具体事实核验规则，不能仅因负面情绪断言违法、责任或胜诉概率。

引用包含标题、发布机构、原始链接、适用地域、相关生效信息、检索时间及支撑的具体论点。优先官方法律法规、司法机关和主管部门公开来源；无法取得或核验原文时显示“依据待核验”，不生成虚构条号。事实不足时给出待补充问题和材料整理步骤，而非确定法律结论。原型所有法律内容均标记为演示，不能伪装成实时核验结果。

### 6.3 状态与恢复

“筛选中”“待确认”“分析中”“部分完成”“分析失败”“完成”分别表达不同阶段。正式保存后，报告或某个附件处理失败不会丢失记录；能看到已完成部分，单独重试失败任务。

## 7. R06：Day One 手动 JSON 导入

### 7.1 导出与导入

用户在 Day One for Mac 选择“文件 → 导出 → JSON”，取得包含 JSON 和媒体目录的 ZIP；也可只导出所选日记本或条目。应用只读取用户选定的 ZIP，逐条先筛选，再把相关事件和所需附件写入本机工作区。导入前显示模型调用与媒体发送范围，由用户确认。原始 Day One 日记及导出 ZIP 不由本应用修改或删除。

### 7.2 后续变化与去重

本版没有自动同步、定时检查或 Day One 直连。需要更新时用户重新导出并导入；同一条目同一版本不产生重复正式记录，旧日记改写后可以重新筛选。曾被跳过的条目不会保留负向指纹，因此再次导入会重新调用模型。既有正式记录的新版本转为无关时不删除旧记录，也不复制新普通日常正文。

### 7.3 可见信息

每次导入显示已检查、已收录、已跳过、待确认、失败和媒体缺失数量；失败不计为跳过。只说明所选 ZIP 内的检查结果，不称为“已连接 Day One”或“全部日记已同步”。媒体缺失、格式不支持或模型能力不足时保留可重试状态，不凭文字单独判定无关。

## 8. R07：时间线与详情

- 默认按时间倒序，按日期分组；支持日期、类别和来源筛选。
- 有明确发生时间则使用发生时间；否则使用日记日期或手动记录日期，并标注“记录日期”；大约日期保持原精度，不显示虚构时分。
- 卡片显示标题、摘要、类别、来源、媒体数量和报告状态；整体可点击，键盘可进入。
- 详情以报告为主，原文及原件可切换查看；返回时恢复列表筛选和位置。
- 没有记录时只显示新建和导入 Day One 两个入口，不用日常示例填充正式列表。

## 9. R08：多模态搜索

输入文字、图片、音频或视频，可添加文字限定描述；搜索覆盖正式记录原文、报告、用户补充和附件片段。

结果按记录聚合，展示匹配解释和来源片段。点击文字跳到对应段落；图片定位到原图；音频和视频定位到时间区间。相关性不显示为事实可信度。

支持时间、类别、来源筛选及分页。索引尚未完成时显示可搜索范围；缺少向量能力时文字关键词检索仍可用，并明确说明受限部分。媒体检索不可用时不能返回“没有相关记录”来冒充正常检索结果。

查询附件仅用于当前搜索，不能变成正式记录、待确认项或搜索索引。音频查询首版依据语义、转写和声音描述，不承诺声纹认人或精确声音指纹匹配。

## 10. R01、R09、R10：设置与数据

模型设置仅呈现百炼和 MiniMax。界面提供服务商、推荐模型、密钥和连接测试，百炼地域与业务空间放在必要配置区；模型支持的文字、图片、音频、视频、检索能力清楚可见。不要求用户理解 Agent 工具调用才可选择分析模型。

百炼作为默认完整能力方案，MiniMax 可作为主分析模型；未覆盖的任务由用户已配置并授权的百炼能力补齐，没有配置则明确显示不可用，不偷偷切换服务商。

设置还包含 Day One 手动导入、默认法律地域、数据迁移和基础存储状态。模型密钥由用户最后在本机配置，不能写进仓库、日志或合成样本；首次真实导入说明筛选、分析与媒体发送范围，日常保存不重复弹窗。

旧版升级使用新工作区筛选迁移，原工作区保留供回退。相关记录、修订、附件及用户补充保留；普通日常不复制进新库，模糊内容进入待确认。旧聊天、人物、案件数据不因存在而自动成为新正式记录，来源引用须有迁移映射。

## 12. 验收示例

| 编号 | 输入／操作 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 三个入口提交普通日常 | 零正式记录、零逐条来源、零派生物，仅来源级统计变化 |
| A02 | 正常正文＋含威胁的媒体 | 综合理解后收录或待确认，不凭正文跳过 |
